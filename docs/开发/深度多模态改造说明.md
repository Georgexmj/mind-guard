# 深度多模态改造说明

**项目：** 基于多模态交互的社区老年认知障碍早期筛查与干预系统  
**版本：** v1.1（深度模型集成版）  
**日期：** 2026-03-31

---

## 1. 改造目标

本次改造在不破坏现有评估流程的前提下，引入深度多模态推理能力，并保留规则模型兜底，核心目标如下：

1. 支持深度跨模态融合模型在线推理。
2. 提供 `rule / deep / hybrid` 三种可切换模型策略。
3. 在深度模型不可用时自动回退，保障服务连续性。
4. 增强结果可解释性字段，标识实际使用模型路径。
5. 提供可执行训练脚本，产出可部署 checkpoint。

## 3. 总体架构（改造后）

评估完成后，仍由 Celery 异步触发分析任务，但推理核心变为“规则基线 + 可选深度推理”：

1. 提取四模态特征：`questionnaire / voice / drawing / behavior`
2. 计算规则基线结果（始终执行）
3. 根据 `AI_MODEL_STRATEGY` 决定：
   - `rule`：直接输出规则结果
   - `deep`：尝试深度模型，失败则回退规则
   - `hybrid`：规则与深度按权重融合
4. 生成风险等级、解释性结果、建议文案并入库
5. 返回结果时附带模型来源信息

---

## 4. 模型策略说明

### 4.1 `rule`

仅使用现有规则模型，稳定、无额外模型依赖。

### 4.2 `deep`

仅使用深度模型输出（概率、域分、模态贡献）。若深度模型不可用，自动回退到规则输出并在 `engine_info` 记录原因。

### 4.3 `hybrid`（推荐）

规则与深度结果融合：

1. 概率融合：`P = (1-α)*P_rule + α*P_deep`
2. 域分融合：`S = (1-α)*S_rule + α*S_deep`
3. 置信度融合：按同一 `α` 线性融合

其中 `α` 由 `DEEP_MODEL_BLEND_ALPHA` 控制，默认 `0.65`。

---

## 5. 新增配置项

```env
AI_MODEL_STRATEGY=hybrid
DEEP_MODEL_CHECKPOINT=models/deep_multimodal_fusion.pt
DEEP_MODEL_DEVICE=cpu
DEEP_MODEL_ALLOW_RANDOM_INIT=false
DEEP_MODEL_BLEND_ALPHA=0.65
```

说明：

1. `AI_MODEL_STRATEGY`：`rule | deep | hybrid`，非法值自动回退 `hybrid`。
2. `DEEP_MODEL_CHECKPOINT`：深度模型权重路径。
3. `DEEP_MODEL_DEVICE`：`cpu | cuda`，若指定 `cuda` 但不可用会自动降级 `cpu`。
4. `DEEP_MODEL_ALLOW_RANDOM_INIT`：
   - `false`：无 checkpoint 则深度模型不可用，触发回退
   - `true`：允许随机初始化运行（仅用于开发联调，不建议生产）
5. `DEEP_MODEL_BLEND_ALPHA`：混合策略深度权重，范围 `[0,1]`。

## 6. 深度模型推理说明

`deep_model_service.py` 采用跨模态注意力结构：

1. 四模态分别编码到统一隐空间
2. 执行 Multi-Head Cross-Attention
3. 输出三类风险概率（NC/MCI/AD）
4. 输出六维认知域分数（0~10）
5. 输出模态贡献度（百分比）
6. 输出注意力矩阵（4x4）

当前实现支持 checkpoint 加载与在线推理，接口为：

- `get_deep_model_service().predict(modality_features)`

## 7. 训练与产物

### 7.1 训练脚本

`backend/scripts/train_deep_multimodal.py`

### 7.2 输入数据格式（CSV）

1. 标签列：
   - `target_class`：`0/1/2`（NC/MCI/AD）
   - 可选：`target_domain_memory` ~ `target_domain_executive`（0~10）
2. 特征列前缀：
   - `questionnaire_*`
   - `voice_*`
   - `drawing_*`
   - `behavior_*`

### 7.3 训练示例

```bash
cd backend
python -m scripts.train_deep_multimodal --input ../data/deep_train.csv --output models/deep_multimodal_fusion.pt
```

生成产物：

- `backend/models/deep_multimodal_fusion.pt`

## 8. API 结果字段变更

`ResultOut` 及任务返回新增字段：

1. `model_name`
2. `model_strategy`
3. `engine_info`
4. `attention_matrix`
5. `model_confidence`
6. `modality_quality`
7. `modality_contributions`
8. `top_factors`

## 10. 验证清单

建议按以下顺序验收：

1. 语法验证：`python -m compileall backend/app backend/scripts`
2. `rule` 模式：评估流程成功、结果正常返回
3. `deep` 模式（有 checkpoint）：返回 `model_name=deep_cross_modal_fusion`
4. `deep` 模式（无 checkpoint）：自动回退且 `engine_info` 包含原因
5. `hybrid` 模式：返回融合结果与模型标识
6. 前端/管理端查看结果页无字段解析报错

---

## 11. 回滚方案

若需快速回滚到稳定路径：

1. 将 `AI_MODEL_STRATEGY` 设置为 `rule`
2. 重启 backend 与 celery worker
3. 深度模型文件可保留，不影响规则链路

---

## 12. 风险与注意事项

1. 未安装 `torch` 时，深度模型不可用，但系统会自动回退。
2. 无有效 checkpoint 时，`deep/hybrid` 依赖回退机制；生产不建议开启随机初始化。
3. 当前训练脚本使用表格特征监督训练，后续可继续升级为端到端多模态训练。
4. 若需要显著提升精度，建议优先完善真实转写/视觉特征链路与标注数据规模。

---
