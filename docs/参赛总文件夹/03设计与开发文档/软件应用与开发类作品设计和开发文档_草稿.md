## 1. 作品概述

### 1.1 作品背景

随着老龄化程度加深，认知障碍早期筛查和社区干预成为基层健康管理的重要需求。轻度认知障碍阶段具有较好的干预窗口，但社区场景中存在专业医生不足、传统量表施测效率低、老年人数字产品使用困难等问题。

### 1.2 作品目标

本作品希望提供一套社区可部署、老人易使用、医生易管理的智能筛查与干预系统，实现：

- 老人端低门槛完成认知评估。
- 后端自动分析评估结果并生成报告。
- 医生端完成重点人群管理和干预计划制定。
- 老人持续打卡，系统识别依从性风险并提醒医生处理。

## 2. 需求分析

### 2.1 用户角色

| 角色 | 需求 |
| --- | --- |
| 老年用户 | 简单登录、按引导完成评估、查看通俗结果、完成干预训练 |
| 家属 | 绑定老人、查看授权数据、接收风险提醒 |
| 社区医生 | 查看老人档案、评估报告、制定干预计划、处理预警 |
| 管理员 | 管理社区、题库、用户和整体数据 |

### 2.2 功能需求

- 账号认证与角色权限。
- 认知评估会话管理。
- 题库管理与作答记录。
- 语音和绘图任务采集。
- AI 风险分析和领域得分。
- 报告、趋势和 PDF 导出。
- 干预推荐、计划、打卡、依从性工单。
- 通知提醒与微信绑定。
- RAG 知识库管理。

### 2.3 非功能需求

- 老年友好：大字号、低层级、任务引导清晰。
- 可部署：支持 Docker Compose 一键启动。
- 可扩展：AI 推理策略和知识库可替换。
- 安全：JWT 鉴权、角色权限、生产密钥替换。

## 3. 系统设计

### 3.1 总体架构

```text
微信小程序 / Web 管理端
        │
      Nginx
        │
FastAPI 后端服务
        │
MySQL / Redis / MinIO / Celery
```

### 3.2 后端设计

后端采用 FastAPI 分层架构：

- Router：HTTP 接口、参数校验、权限检查。
- Service：业务逻辑、AI 分析、报告生成。
- Model：SQLAlchemy ORM 表结构。
- Task：Celery 异步任务。

核心路由：

- `/api/v1/auth`
- `/api/v1/users`
- `/api/v1/assessments`
- `/api/v1/questions`
- `/api/v1/dashboard`
- `/api/v1/interventions`
- `/api/v1/notifications`
- `/api/v1/rag`

### 3.3 前端设计

Web 管理端使用 React、TypeScript、Ant Design 和 ECharts，主要页面包括登录、管理看板、老人列表、老人详情、评估管理、干预管理、题库管理和通知中心。

### 3.4 小程序设计

小程序使用 UniApp 和 Vue 3，主要页面包括登录、首页、评估说明、认知题目、语音任务、时钟绘图、结果页、干预训练和个人中心。

### 3.5 数据库设计

核心表包括：

- `users`、`communities`、`user_relationships`、`wechat_bindings`
- `questions`、`assessment_sessions`、`assessment_responses`、`assessment_results`
- `intervention_plans`、`intervention_records`、`intervention_adherence_tickets`
- `notifications`
- `rag_knowledge_items`

## 4. AI 与算法设计

系统支持三种推理策略：

| 策略 | 说明 |
| --- | --- |
| `rule` | 规则模型，保证稳定演示 |
| `deep` | 深度多模态融合模型 |
| `hybrid` | 规则与深度模型融合，当前推荐 |

AI 输出包括风险等级、NC/MCI/AD 概率、MMSE 等效分、领域得分、解释字段和干预建议。

## 7. 作品特色

- 适合社区落地的多角色协同流程。
- 结合小程序与 Web 管理端，兼顾老人低门槛和医生高效率。
- 将评估结果与干预执行连接，形成闭环。
- AI 推理策略可配置，便于演示和后续扩展。
