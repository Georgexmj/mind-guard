# 数据库设计文档

**项目：** 基于多模态交互的社区老年认知障碍早期筛查与干预系统
**数据库：** MySQL 8.0
**版本：** v1.0 | 2026-03

---

## 一、数据库总体设计

### 1.1 数据库划分

| 数据库名 | 说明 |
|----------|------|
| `cognitive_db` | 主业务数据库（本文档涵盖） |
| `cognitive_ai` | AI引擎内部数据（模型版本、实验记录，由MLflow管理） |

### 1.2 字符集与排序规则

```sql
CHARACTER SET = utf8mb4
COLLATE = utf8mb4_unicode_ci
```

### 1.3 命名规范

- 表名：小写下划线，复数形式（`users`, `assessment_sessions`）
- 字段名：小写下划线（`created_at`, `risk_level`）
- 主键：统一命名 `id`，BIGINT AUTO_INCREMENT
- 外键字段：`{表名单数}_id`（如 `user_id`, `session_id`）
- 时间字段：`created_at`（创建）、`updated_at`（更新）、`deleted_at`（软删除）

---

## 二、ER关系总览

```
communities (社区)
    └──< users (用户)                          [一个社区多个用户]
         ├──< user_relationships (家属关系)    [老人↔家属 多对多桥接]
         ├──< assessment_sessions (评估会话)   [一个用户多次评估]
         │    ├──< modality_data (模态数据)   [每次评估多条模态记录]
         │    ├──< assessment_questions (作答明细) [每次评估多道题]
         │    └──1 assessment_results (评估结果) [每次评估一条综合结果]
         └──< intervention_plans (干预计划)   [一个用户多个干预计划]
              └──< intervention_records (干预执行记录)

question_bank (题库)                           [独立题目库]
    └──< assessment_questions.question_id (外键引用)
```

## 三、核心表结构详细设计

### 3.1 communities — 社区信息表

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | BIGINT | PK, AUTO_INCREMENT | 主键 |
| name | VARCHAR(100) | NOT NULL | 社区名称 |
| province | VARCHAR(20) | NOT NULL | 省份 |
| city | VARCHAR(50) | NOT NULL | 城市 |
| district | VARCHAR(50) | NOT NULL | 区/县 |
| address | TEXT | | 详细地址 |
| longitude | DECIMAL(10,7) | | 经度（GIS可视化） |
| latitude | DECIMAL(10,7) | | 纬度（GIS可视化） |
| elder_count | INT | DEFAULT 0 | 注册老人数量 |
| manager_id | BIGINT | FK → users.id | 负责管理员 |
| created_at | DATETIME | NOT NULL | 创建时间 |
| updated_at | DATETIME | NOT NULL | 更新时间 |

### 3.2 users — 用户主表

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | BIGINT | PK, AUTO_INCREMENT | 主键 |
| uuid | VARCHAR(36) | UNIQUE, NOT NULL | 对外唯一标识（UUID v4） |
| phone_encrypted | VARCHAR(255) | UNIQUE | 手机号（AES-256加密） |
| name | VARCHAR(50) | NOT NULL | 真实姓名 |
| birth_date | DATE | NOT NULL | 出生日期 |
| gender | TINYINT | NOT NULL | 0:女 1:男 |
| education_years | TINYINT | DEFAULT 0 | 受教育年限（影响量表评分校正） |
| role | ENUM | NOT NULL | 'elder', 'family', 'doctor', 'admin' |
| community_id | BIGINT | FK → communities.id | 所属社区 |
| face_embedding | BLOB | | 人脸特征向量（人脸登录，加密） |
| voice_print | BLOB | | 声纹特征（声纹登录） |
| is_active | TINYINT | DEFAULT 1 | 账号是否启用 |
| last_login_at | DATETIME | | 最后登录时间 |
| created_at | DATETIME | NOT NULL | 注册时间 |
| updated_at | DATETIME | NOT NULL | 信息更新时间 |
| deleted_at | DATETIME | NULL | 软删除时间 |

**备注：**
- `education_years` 用于MMSE/MoCA分数校正（文盲老人的语言类题目分数需上调基准线）
- 人脸/声纹特征向量加密存储，不保存原始生物特征图像/音频

### 3.3 user_relationships — 家属-老人绑定关系表

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | BIGINT | PK | 主键 |
| elder_id | BIGINT | FK → users.id | 老年用户ID |
| family_id | BIGINT | FK → users.id | 家属用户ID |
| relationship | VARCHAR(20) | NOT NULL | 关系：子女/配偶/兄弟姐妹/其他 |
| notify_level | TINYINT | DEFAULT 1 | 0:不通知 1:高危才通知 2:全部通知 |
| is_primary | TINYINT | DEFAULT 0 | 是否主要联系人 |
| created_at | DATETIME | NOT NULL | 绑定时间 |

**索引：** `(elder_id, family_id)` UNIQUE，一对关系只能绑定一次

### 3.4 assessment_sessions — 评估会话主表

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | BIGINT | PK | 主键 |
| session_uuid | VARCHAR(36) | UNIQUE, NOT NULL | 会话UUID |
| user_id | BIGINT | FK → users.id | 参与评估的老人 |
| operator_id | BIGINT | FK → users.id, NULL | 辅助操作的医护人员（可空） |
| assessment_type | ENUM | NOT NULL | 'screening'(5分钟)/''full'(25分钟)/'followup'(随访) |
| status | ENUM | NOT NULL | 'in_progress'/'completed'/'abandoned'/'analyzing' |
| started_at | DATETIME | NOT NULL | 评估开始时间 |
| completed_at | DATETIME | NULL | 评估完成时间 |
| total_duration | INT | NULL | 总用时（秒） |
| device_type | VARCHAR(20) | | 'tablet'/'phone'/'web' |
| device_os | VARCHAR(30) | | 操作系统版本 |
| ai_task_id | VARCHAR(64) | NULL | Celery任务ID（查询异步状态） |
| created_at | DATETIME | NOT NULL | 记录创建时间 |

**索引：** `(user_id, started_at)` 联合索引，按用户查历史评估高频

### 3.5 assessment_results — 评估综合结果表

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | BIGINT | PK | 主键 |
| session_id | BIGINT | FK → assessment_sessions.id, UNIQUE | 一次评估对应一条结果 |
| mmse_score | TINYINT | NULL | MMSE得分（0~30） |
| moca_score | TINYINT | NULL | MoCA得分（0~30） |
| cognitive_score | DECIMAL(5,2) | NOT NULL | 系统综合认知评分（0~100） |
| risk_level | ENUM | NOT NULL | 'low'/'medium'/'high'/'very_high' |
| risk_probability | DECIMAL(4,3) | NOT NULL | 认知障碍概率（0.000~1.000） |
| classification | ENUM | NOT NULL | 'NC'/'MCI'/'mild_AD'/'uncertain' |
| confidence | DECIMAL(4,3) | NOT NULL | 分类置信度（0.000~1.000） |
| memory_score | DECIMAL(5,2) | | 记忆域得分 |
| attention_score | DECIMAL(5,2) | | 注意域得分 |
| executive_score | DECIMAL(5,2) | | 执行功能域得分 |
| language_score | DECIMAL(5,2) | | 语言域得分 |
| visuospatial_score | DECIMAL(5,2) | | 视空间域得分 |
| orientation_score | DECIMAL(5,2) | | 定向力域得分 |
| shap_values_json | JSON | NULL | SHAP特征贡献度（可解释性数据） |
| ai_analysis_json | JSON | NULL | AI分析完整输出（各模态分析详情） |
| report_pdf_path | VARCHAR(255) | NULL | MinIO中PDF报告路径 |
| created_at | DATETIME | NOT NULL | 结果生成时间 |

**设计说明：**
- `shap_values_json` 示例：`{"voice_fluency": 0.38, "memory_recall": 0.31, "clock_drawing": 0.18, "reaction_time": 0.13}`
- `cognitive_score` 是系统综合评分，非单一量表得分，由AI模型输出后归一化到0~100

### 3.6 modality_data — 多模态原始数据记录表

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | BIGINT | PK | 主键 |
| session_id | BIGINT | FK → assessment_sessions.id | 所属评估会话 |
| modality_type | ENUM | NOT NULL | 'voice'/'face_video'/'handwriting'/'behavior'/'questionnaire' |
| task_name | VARCHAR(50) | NOT NULL | 任务名称（如'picture_description', 'clock_drawing', 'word_fluency'） |
| file_path | VARCHAR(255) | NULL | MinIO对象路径（音视频文件） |
| raw_features_json | JSON | NULL | 提取的特征向量（存于MongoDB则此处存引用ID） |
| quality_score | DECIMAL(3,2) | NULL | 数据质量评分（0.00~1.00，低于0.6需重采） |
| processing_status | ENUM | NOT NULL | 'pending'/'processing'/'done'/'failed' |
| error_message | TEXT | NULL | 处理失败原因 |
| duration_ms | INT | NULL | 录音/录像时长（毫秒） |
| created_at | DATETIME | NOT NULL | 上传时间 |

**设计说明：**
- 音视频大文件存储于MinIO，此处仅记录路径
- 对于数据质量低（如录音有严重噪音、手写图像模糊）的数据，`quality_score < 0.6` 时前端提示用户重新录制

### 3.7 assessment_questions — 题目作答明细表

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | BIGINT | PK | 主键 |
| session_id | BIGINT | FK → assessment_sessions.id | 所属评估会话 |
| question_id | BIGINT | FK → question_bank.id | 题目ID |
| question_order | TINYINT | NOT NULL | 本次评估中的题目序号 |
| answer_value | JSON | NULL | 作答内容（不同题型结构不同） |
| is_correct | TINYINT | NULL | 0:错误 1:正确 NULL:开放题/待AI评分 |
| ai_score | DECIMAL(4,2) | NULL | AI评分（用于手写/语音开放题） |
| response_time_ms | INT | NOT NULL | 答题用时（毫秒） |
| revision_count | TINYINT | DEFAULT 0 | 答题中途修改次数 |
| created_at | DATETIME | NOT NULL | 作答时间 |

**answer_value 示例：**
```json
// 单选题
{"selected": "B", "options": ["A","B","C","D"]}
// 语音作答
{"transcription": "今天是三月二十六号", "audio_path": "minio://sessions/xxx/q5.wav"}
// 手写坐标序列
{"strokes": [[{"x":100,"y":200,"t":0},{"x":101,"y":201,"t":50}]], "image_path": "minio://sessions/xxx/clock.png"}
```

### 3.8 question_bank — 题库表

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | BIGINT | PK | 主键 |
| cognitive_domain | ENUM | NOT NULL | 'memory'/'attention'/'executive'/'language'/'visuospatial'/'orientation' |
| scale_type | ENUM | NOT NULL | 'mmse'/'moca'/'custom' |
| question_type | ENUM | NOT NULL | 'single_choice'/'voice_answer'/'drawing'/'sequence'/'calculation'/'image_naming' |
| difficulty | DECIMAL(3,2) | DEFAULT 0.00 | IRT难度参数 b（-3.00~3.00，0为中等） |
| discrimination | DECIMAL(3,2) | DEFAULT 1.00 | IRT区分度参数 a（>0） |
| content_json | JSON | NOT NULL | 题目内容（支持文字/图片/音频多媒体） |
| scoring_rule_json | JSON | NOT NULL | 评分规则（关键词/正则/坐标范围） |
| time_limit_sec | SMALLINT | DEFAULT 60 | 建议作答时限（秒） |
| tags | VARCHAR(200) | | 标签（逗号分隔，如 "延迟回忆,图片"） |
| is_active | TINYINT | DEFAULT 1 | 是否启用 |
| created_at | DATETIME | NOT NULL | 创建时间 |

**content_json 示例（图片命名题）：**
```json
{
  "stem": "请说出图片中的物品名称",
  "image_url": "minio://question-bank/images/camel.jpg",
  "answer_mode": "voice",
  "hint_text": "（动物）"
}
```

### 3.9 intervention_plans — 干预计划表

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | BIGINT | PK | 主键 |
| user_id | BIGINT | FK → users.id | 目标老人 |
| creator_id | BIGINT | FK → users.id | 制定者（医生ID或系统自动生成填0） |
| source | ENUM | NOT NULL | 'ai_recommend'/'doctor_manual' |
| plan_type | ENUM | NOT NULL | 'cognitive_training'/'music'/'exercise'/'social'/'lifestyle'/'medication' |
| priority | TINYINT | NOT NULL | 优先级 1(低)~5(高) |
| title | VARCHAR(100) | NOT NULL | 方案标题 |
| description | TEXT | | 详细描述 |
| start_date | DATE | NOT NULL | 开始日期 |
| end_date | DATE | NULL | 结束日期 |
| frequency | VARCHAR(50) | | 频率描述（如"每天10分钟"） |
| target_domain | VARCHAR(100) | | 针对的认知域（逗号分隔） |
| content_json | JSON | | 具体内容（游戏ID、视频链接等） |
| status | ENUM | NOT NULL | 'active'/'completed'/'abandoned'/'paused' |
| created_at | DATETIME | NOT NULL | 创建时间 |
| updated_at | DATETIME | NOT NULL | 更新时间 |

### 3.10 intervention_records — 干预执行记录表

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | BIGINT | PK | 主键 |
| plan_id | BIGINT | FK → intervention_plans.id | 所属计划 |
| user_id | BIGINT | FK → users.id | 执行用户 |
| executed_at | DATETIME | NOT NULL | 执行时间 |
| duration_sec | INT | NULL | 实际执行时长（秒） |
| completion_rate | DECIMAL(3,2) | NULL | 完成度（0.00~1.00） |
| feedback_score | TINYINT | NULL | 用户满意度评分（1~5星） |
| notes | TEXT | NULL | 备注 |
| created_at | DATETIME | NOT NULL | 记录创建时间 |

## 四、索引设计

```sql
-- users表
CREATE INDEX idx_users_community ON users(community_id);
CREATE INDEX idx_users_role ON users(role);

-- assessment_sessions表
CREATE INDEX idx_sessions_user_time ON assessment_sessions(user_id, started_at DESC);
CREATE INDEX idx_sessions_status ON assessment_sessions(status);

-- assessment_results表
CREATE INDEX idx_results_risk ON assessment_results(risk_level);
CREATE INDEX idx_results_classification ON assessment_results(classification);

-- modality_data表
CREATE INDEX idx_modality_session ON modality_data(session_id, modality_type);
CREATE INDEX idx_modality_status ON modality_data(processing_status);

-- intervention_plans表
CREATE INDEX idx_interventions_user ON intervention_plans(user_id, status);
```

|----|--------------------|------------|
| users | 500 | ~500B |
