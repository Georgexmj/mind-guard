# 第七章 风险分析

## 7.1 技术风险

### 7.1.1 AI模型准确率不足

**风险描述**：多模态AI模型在小样本、老年方言、低质量录音场景下，MCI识别AUC可能低于预期（目标>0.85），导致漏诊或误诊。

**概率**：高 | **影响**：高

**规避策略**：
1. **降低对单一模型的依赖**：采用两阶段架构，第一阶段LightGBM量表特征筛查（准确率已验证≥0.87），多模态模型作为增强层，竞赛演示以第一阶段为主
2. **数据增强**：使用时间拉伸、噪声注入、语速变换等方式扩充老年语音训练样本
3. **保守标注策略**：模型输出置信度<0.7时，系统建议"建议到医院进行专业评估"，主动降低误诊风险
4. **人工复核通道**：高风险结果自动推送至绑定医生，AI诊断仅作为"辅助参考"，不作医疗诊断

### 7.1.2 微信小程序兼容性与性能风险

**风险描述**：Canvas 2D手写采集、wx.getRecorderManager录音在不同机型（尤其是老旧Android机）可能存在兼容性问题；小程序包大小超过2MB主包限制导致加载缓慢。

**概率**：中 | **影响**：中

**规避策略**：
1. 分包加载（subpackages）：将评估流程页面拆分为独立分包（≤8MB），主包<1MB保证快速启动
2. 真机兼容测试优先：iOS 14+/Android 9+/微信8.0+全机型矩阵测试
3. 降级方案：Canvas 2D不支持时，降级为SVG或图片打点方案
4. 录音质量检测：检测到录音时长<5秒或信噪比过低时，提示用户"请在安静环境中重录"

### 7.1.3 国产ASR方言识别率波动

**风险描述**：粤语、闽南话、四川话等方言语音，部分国产ASR模型在社区场景下WER可能超过25%，影响语言流利度特征质量。

**概率**：高 | **影响**：中

**规避策略**：
1. 提供"普通话朗读"模式，给出朗读提示词（减少即兴语言，降低方言影响）
2. 保留文字备选输入选项，允许用户打字回答
3. 后续迭代引入讯飞方言识别API（商业授权方案）

## 7.2 市场风险

### 7.2.1 大厂竞争风险

**风险描述**：腾讯（微信医疗生态）、阿里（阿里健康）、华为（HiHealth）等大厂可能推出类似功能，凭借流量优势快速侵占市场。

**概率**：中 | **影响**：高

**规避策略**：
1. **专注细分深度**：大厂做"泛健康"，我们做"认知障碍垂直深度"——专病深度优于泛健康广度
2. **数据飞轮**：积累的中文老年认知多模态数据集是真正的护城河，大厂难以快速复制
3. **医学背书差异化**：与三甲医院合作发表论文，建立学术权威性，大厂无法快速复制
4. **B端黏性**：机构客户一旦接入，迁移成本高（数据、工作流、人员培训已完成），续费率有保障

### 7.2.2 B端采购决策周期长

**风险描述**：政府、医院的采购决策周期通常为3~8个月，导致现金流压力和计划延迟。

**概率**：高 | **影响**：中

**规避策略**：
1. 先推C端（个人家庭付费），C端决策周期<1天，快速产生现金流
2. 采用"免费试用3个月→付费续费"模式，降低B端决策阻力
3. 同时推进多个B端客户（漏斗足够宽，总有部分客户会成交）

### 7.2.3 老年用户数字鸿沟

**风险描述**：目标用户60~80岁老年群体中，30%以上不会独立使用智能手机，导致产品使用率低于预期。

**概率**：高 | **影响**：中

**规避策略**：
1. 产品核心设计原则：老人不会用 → 家属帮助操作也能完成（家属代操模式）
2. 大字体、语音引导、简化步骤（每屏只有一个操作）
3. 社区现场辅导服务：志愿者/社区工作人员现场引导首次使用
4. 视频教程嵌入小程序内，30秒快速上手

## 7.3 财务风险

### 7.3.1 B端付费意愿低/价格敏感

**风险描述**：社区卫生服务中心预算有限，8,800元/年的订阅费可能超出其可接受范围，尤其在无政府补贴的情况下。

**概率**：中 | **影响**：高

**规避策略**：
1. 政府补贴撬动：将系统申报为"卫健委推荐认知筛查工具"，争取政府项目资金覆盖机构费用
2. 降低入门门槛：提供免费基础版（仅限前100次评估），超出后付费
3. 性价比证明：测算替代成本——医院聘请1名医生做量表测评的年薪 > 5万元，本系统仅需8,800元

### 7.3.2 C端用户付费留存率低

**风险描述**：C端用户评估完1次后流失，不续费，LTV低于预期。

**概率**：中 | **影响**：中

**规避策略**：
1. 强调纵向追踪价值："单次评估不重要，6个月趋势变化才是关键"
2. 推出月度健康报告推送（微信消息），维持用户感知价值
3. 家属共同使用设计（子女绑定查看父母报告），提高关系型黏性
4. 定期评估提醒（每3个月提醒一次），降低遗忘流失

### 7.3.3 融资失败/资金链断裂

**风险描述**：如果种子轮融资不顺利，团队全职转型后资金可能在12个月内耗尽。

**概率**：低（竞赛期无此压力）| **影响**：高（全职转型后）

**规避策略**：
1. 竞赛阶段保持学生身份，无人力成本，资金压力极小
2. 设定明确的盈亏平衡节点：年收入达30万元后才考虑全职转型
3. 多元融资来源：学校基金、政府补贴、大学生创业基金三条腿并行
4. 轻资产运营：避免过早租办公室、购买昂贵设备

## 7.4 合规与伦理风险

### 7.4.1 医疗合规风险

**风险描述**：系统涉及认知障碍判断，若被界定为"医疗器械"，需要通过NMPA注册（耗时1~3年，费用数百万元），否则违规。

**概率**：中 | **影响**：高

**规避策略**：
1. **产品定位为"健康管理工具"而非"诊断工具"**：报告结语固定注明"本评估结果仅供参考，不构成医学诊断，如有疑虑请到医院就诊"
2. 咨询专业医疗器械法规顾问，确认分类（目标：第一类或豁免类）
3. 参考"微医""丁香医生"等平台的合规边界，学习已有案例
4. 避免在产品描述中使用"诊断""治疗""阿尔茨海默病"等敏感词

### 7.4.2 数据隐私与安全风险

**风险描述**：系统收集老年人面部特征、声纹、认知数据等高度敏感的生物特征和健康数据，一旦泄露将造成严重后果并面临《个人信息保护法》处罚。

**概率**：低（技术层面有防护）| **影响**：极高

**规避策略**：
1. **数据最小化原则**：面部特征、声纹仅存储加密后的特征向量，不存储原始图像/音频（评估完成后48小时内自动删除原始文件）
2. **传输加密**：全程HTTPS + 数据传输额外AES-256加密
3. **知情同意**：用户首次使用必须完成知情同意书签署（电子签名留存）
4. **数据访问控制**：RBAC权限体系，医生只能访问其绑定老人数据，管理员不可访问个人健康数据

### 7.4.3 AI伦理风险（算法歧视）

**风险描述**：AI模型可能对低学历、少数民族、方言用户存在系统性偏差（教育偏倚是MMSE量表的已知问题），导致不公平的诊断结果。

**概率**：中 | **影响**：中

**规避策略**：
1. 在评估引擎中引入"教育年限校正"（MMSE原版已有此设计），输入用户受教育年限进行得分校正
2. 训练数据覆盖多元化群体（不同年龄、学历、地域），避免分布偏移
3. 报告中明确标注"AI评估存在局限性，方言用户评分可能偏低，建议结合医生判断"
