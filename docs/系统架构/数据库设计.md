# 数据库设计文档

**当前口径：** 以 `backend/app/models/*.py` 的 SQLAlchemy ORM 为准  
**修订日期：** 2026-04-29

## 一、总览

当前核心业务表由后端启动时通过 `Base.metadata.create_all(bind=engine)` 创建，种子数据由 `python -m app.initial_data` 写入。

```text
communities
  └── users
        ├── user_relationships
        ├── wechat_bindings
        ├── assessment_sessions
        │     ├── assessment_responses
        │     └── assessment_results
        ├── intervention_plans
        │     ├── intervention_records
        │     └── intervention_adherence_tickets
        └── notifications

questions
  └── assessment_responses

rag_knowledge_items
```

## 二、用户与社区

### `communities`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | Integer PK | 社区 ID |
| `name` | String(200) | 社区名称 |
| `province` | String(50) | 省份 |
| `city` | String(50) | 城市 |
| `district` | String(50) | 区县，可空 |
| `address` | String(500) | 地址，可空 |
| `elder_count` | Integer | 老人数量缓存 |
| `created_at` | DateTime | 创建时间 |

### `users`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | Integer PK | 用户 ID |
| `uuid` | String(36) unique | 对外 UUID |
| `phone` | String(20) unique | 手机号 |
| `id_card` | String(18) unique nullable | 身份证号 |
| `name` | String(100) | 姓名 |
| `birth_date` | Date nullable | 出生日期 |
| `gender` | String(10) nullable | 性别 |
| `education_years` | Integer nullable | 受教育年限 |
| `role` | Enum | `elder`、`family`、`doctor`、`admin` |
| `community_id` | FK | 所属社区 |
| `password_hash` | String(255) | 密码哈希 |
| `is_active` | Boolean | 是否启用 |
| `last_login_at` | DateTime nullable | 最近登录 |
| `created_at`, `updated_at` | DateTime | 创建/更新时间 |

### `user_relationships`

家属与老人绑定关系。

| 字段 | 说明 |
| --- | --- |
| `elder_id` | 老人用户 ID |
| `family_id` | 家属用户 ID |
| `relationship` | 关系，如 `son`、`daughter`、`spouse` |
| `notify_level` | 通知等级：1 全部，2 仅高风险，3 不通知 |
| `is_primary` | 是否主要联系人 |

### `wechat_bindings`

微信 openid/unionid 与系统用户绑定关系，用于小程序与订阅消息。

| `completed_at` | 完成时间 |

| --- | --- |

## 四、干预闭环

### `intervention_plans`

医生或管理员为老人创建的干预计划。

| 字段 | 说明 |
| --- | --- |
| `elder_id` | 老人 |
| `created_by` | 创建人 |
| `title` | 计划标题 |
| `description` | 计划说明 |
| `domain_focus` | 目标认知领域，逗号分隔 |
| `frequency` | 频次 |
| `duration_days` | 计划天数 |
| `start_date`, `end_date` | 起止日期 |
| `status` | `active`、`paused`、`completed`、`cancelled` |
| `ai_priority` | AI 推荐优先级 |

### `intervention_records`

老人执行记录或每日打卡。

| 字段 | 说明 |
| --- | --- |
| `plan_id` | 计划 |
| `elder_id` | 老人 |
| `record_date` | 执行日期 |
| `completed` | 是否完成 |
| `duration_min` | 执行分钟数 |
| `notes` | 备注 |
| `mood_score` | 心情评分 1-5 |

### `intervention_adherence_tickets`

依从性预警工单。

| 字段 | 说明 |
| --- | --- |
| `plan_id`, `elder_id` | 关联计划与老人 |
| `status` | `open`、`in_progress`、`resolved`、`ignored` |
| `owner_doctor_id` | 负责医生 |
| `reminder_at` | 提醒时间 |
| `followup_note` | 随访备注 |
| `consecutive_missed_days` | 连续漏打卡天数 |
| `completion_rate` | 完成率 |
| `latest_interruption_reason` | 最近中断原因 |
| `risk_level` | 最近风险等级快照 |

## 六、当前边界

- `InfluxDB` 与 `MongoDB` 已纳入 Docker 编排，但当前核心 ORM 业务表仍以 MySQL 为主。
- 当前未使用 Alembic 迁移目录；开发和演示环境依赖 SQLAlchemy 自动建表。
- 若进入生产或多人协作开发，建议补齐 Alembic 迁移，并停止依赖自动建表变更结构。
