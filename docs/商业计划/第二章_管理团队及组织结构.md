# 第二章 管理团队及组织结构

## 2.1 团队概览

本项目由来自计算机科学与技术、人工智能、临床医学、产品设计等多学科交叉背景的学生团队组成，指导教师具备深厚的AI医疗和系统工程经验。团队规模**6人+2位指导教师**，覆盖项目从算法研发到产品落地的完整能力链。

---

## 2.2 核心成员介绍

### 2.2.1 项目负责人（CEO / 技术架构）

**职责**：整体技术架构设计、项目进度管理、对外沟通与汇报

**背景与能力**：
- 计算机科学与技术专业，熟悉全栈开发（Python/FastAPI、React）
- 主导过校级科研项目，具备系统架构设计经验
- 熟悉机器学习工程化流程（模型训练 → 部署 → A/B测试）
- 曾获省级软件创新大赛三等奖

**核心贡献**：系统架构设计、后端服务开发、团队协调

---

### 2.2.2 AI算法工程师

**职责**：多模态融合模型设计与训练、AI推理服务部署

**背景与能力**：
- 人工智能专业，具备深度学习项目实战经验
- 熟练掌握PyTorch 2.x、Transformers、LightGBM、SHAP
- 完成过基于BERT的文本分类项目（准确率92%+）
- 了解语音信号处理（LibROSA、OpenSMILE、Whisper）

**核心贡献**：Cross-Modal Attention模型实现、SHAP可解释性模块、LightGBM阶段一筛查器

---

### 2.2.3 后端开发工程师

**职责**：RESTful API开发、数据库设计、Celery异步任务

**背景与能力**：
- 软件工程专业，熟练Python/FastAPI + SQLAlchemy
- 具备MySQL数据库设计经验，了解Redis缓存策略
- 熟悉Docker + Docker Compose容器化部署
- 了解MinIO对象存储与文件管理

**核心贡献**：API接口层开发、数据库Schema设计、异步任务队列

---

### 2.2.4 前端开发工程师（Web Admin）

**职责**：Web管理端开发（医生/管理员平台）

**背景与能力**：
- 计算机专业，熟练React 18 + TypeScript + Ant Design 5
- 熟悉ECharts数据可视化（雷达图、折线图、热力图）
- 具备响应式布局与无障碍设计经验
- 了解Vite构建工具与前端工程化

**核心贡献**：Web管理后台UI、认知雷达图可视化、PDF报告生成

---

### 2.2.5 小程序开发工程师（老年端）

**职责**：微信小程序开发（老年用户评估端）

**背景与能力**：
- 软件工程专业，熟练UniApp + Vue 3 + Pinia
- 熟悉微信原生API（wx.getRecorderManager、Canvas 2D、wx.getTextToSpeech）
- 具备老年无障碍交互设计意识，参与过社区志愿服务了解老年用户习惯
- 熟悉微信订阅消息配置

**核心贡献**：微信小程序端完整实现（登录→评估→结果）、老年友好UI

---

### 2.2.6 医学顾问 / 产品设计

**职责**：认知障碍领域专业知识支撑、量表设计、用户研究

**背景与能力**：
- 临床医学或护理专业背景（或具备老年医学课程基础）
- 了解MMSE、MoCA量表评分规则及临床意义
- 参与过社区老年健康调研，理解老年群体使用习惯
- 负责产品原型设计（Figma）与用户测试方案

**核心贡献**：题库内容设计、评估流程合规性把关、老年用户可用性测试

## 2.4 成员分工与互补性

```
┌─────────────────────────────────────────────────────┐
│                   项目负责人                          │
│              架构 + 项目管理 + 后端核心               │
└──────────────┬──────────────────────────────────────┘
               │
    ┌──────────┼──────────┬─────────────┐
    ▼          ▼          ▼             ▼
 AI算法     后端开发    前端(Web)    小程序(老年端)
 模型训练   API接口     管理后台     微信小程序
 推理服务   数据库      可视化       交互设计
               │
               ▼
          医学顾问+产品
          量表+用研+UI原型
```

**互补性分析**：

| 能力维度 | 覆盖成员 |
|----------|----------|
| AI/机器学习 | AI工程师 + 项目负责人 |
| 后端工程 | 后端工程师 + 项目负责人 |
| 前端开发 | Web工程师 + 小程序工程师 |
| 医学专业 | 医学顾问 + 指导教师一 |
| 产品/设计 | 医学顾问（兼任）|
| 项目管理 | 项目负责人 |

团队形成"算法-工程-医学-设计"四维互补，避免了纯技术团队忽视医学合规、纯医学背景缺乏工程落地能力的常见问题。
