# 微信公众平台逐页点击版（MindGuard 老人端）

本文是“按页面点击”的操作手册，适用于把 MindGuard 老人端小程序接入后端接口并发布上线。

## 0. 先准备好这 4 个信息

1. 小程序 `AppID`
2. 后端 HTTPS 地址（示例：`https://api.xxx.com`）
3. 接口前缀（本项目为：`/api/v1`）
4. 管理员微信（可登录微信公众平台）

最终小程序里要用的完整 API 基地址示例：`https://api.xxx.com/api/v1`

## 1. 登录并进入目标小程序

1. 浏览器打开 `https://mp.weixin.qq.com`
2. 扫码登录管理员账号
3. 如果一个账号下有多个小程序，先点进 `MindGuard` 对应小程序后台

## 2. 配置服务器域名（最关键）

### 2.1 打开页面路径

1. 左侧菜单点击 `开发`
2. 点击 `开发管理`
3. 点击页签 `开发设置`
4. 在页面中找到 `服务器域名`

### 2.2 填写 request 合法域名

1. 在 `request 合法域名` 处点 `修改`
2. 增加你的 API 域名（只填域名，不带路径）
3. 示例填写：`https://api.xxx.com`
4. 点 `保存`

### 2.3 按需填写其他域名

1. `uploadFile 合法域名`：如果你有 `wx.uploadFile` 再填
2. `downloadFile 合法域名`：如果你有 `wx.downloadFile` 再填
3. `socket 合法域名`：如果你有 WebSocket 再填

当前 MindGuard 老人端主要走 `wx.request`，优先保证 `request 合法域名` 正确。

## 3. 配置业务域名（仅当使用 web-view）

如果你没有内嵌 H5 页面，可以跳过本节。

1. 仍在 `开发 -> 开发管理 -> 开发设置`
2. 找到 `业务域名`
3. 点击配置并按页面提示下载校验文件
4. 把校验文件放到你 H5 站点根目录
5. 回到后台点校验/保存

## 4. 在微信开发者工具导入并联调

1. 打开微信开发者工具
2. 选择 `导入项目`
3. 目录选本仓库小程序目录：`miniprogram`
4. 填写/选择对应 `AppID`
5. 点击 `进入项目`

## 5. 设置小程序 API 基地址

MindGuard 小程序支持三种方式读取 API 地址（优先级从高到低）：

1. 本地缓存 `mindguard_api_base_url`
2. 构建环境变量 `UNI_API_BASE_URL` / `VITE_API_BASE_URL`
3. 默认值 `http://127.0.0.1:8000/api/v1`

开发者工具调试时，推荐在控制台执行：

```js
wx.setStorageSync('mindguard_api_base_url', 'https://api.xxx.com/api/v1')
```

## 6. 逐项联通验证（发布前必须做）

1. 老人账号登录：`13800000003 / elder123`，应登录成功
2. 医生账号登录：`13800000002 / doctor123`，应被拦截并提示使用 Web 管理端
3. 首页可加载历史记录
4. 可进入“开始评估”，能拉到题目
5. 选择题提交成功
6. 语音题录制后返回，点击“下一题”可继续
7. 时钟绘图题提交后可继续
8. 评估完成后结果页可展示风险等级与 MMSE

## 7. 提审与发布（正式上线）

### 7.1 上传代码

1. 微信开发者工具顶部点击 `上传`
2. 填写版本号（如 `1.0.1`）和备注
3. 上传成功后回到微信公众平台

### 7.2 提交审核

1. 微信公众平台左侧点击 `版本管理`
2. 在 `开发版本` 找到刚上传版本
3. 点击 `提交审核`
4. 按页面要求填写功能说明、测试账号、测试路径等
5. 提交后等待审核结果

### 7.3 发布上线

1. 审核通过后，在 `版本管理` 页面点击 `发布`
2. 发布后用手机微信真实环境再跑一次完整流程

## 8. 常见报错对照

1. `request:fail ... url not in domain list`
   - 原因：`request 合法域名` 未配置或填错
2. `request:fail ssl hand shake error`
   - 原因：HTTPS 证书链不完整或证书异常
3. 开发者工具能调通、手机真机不通
   - 原因：常见是合法域名、证书、网关转发配置问题
4. 登录一直失败
   - 检查 API 基地址是否带了正确前缀 `/api/v1`
