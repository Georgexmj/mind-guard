# 项目落地实施规划

**项目：** 基于多模态交互的社区老年认知障碍早期筛查与干预系统
**竞赛：** 全国大学生软件创新大赛
**开发周期：** 10周（含演示准备）
**版本：** v1.0 | 2026-03

---

## 一、团队角色建议

| 角色 | 人数 | 主要职责 |
|------|------|----------|
| 全栈开发（后端为主） | 1~2人 | FastAPI服务、数据库、API接口 |
| AI/ML工程师 | 1~2人 | 多模态特征提取、模型训练、推理服务 |
| 前端开发 | 1人 | React Web管理端 |
| 移动端开发 | 1人 | UniApp微信小程序开发 |
| 产品/测试 | 1人 | 需求管理、测试用例、竞赛材料制作 |

*小团队（3人以下）可以后端+AI为核心，前端做Web端Demo即可，移动端后期补充*

---

## 二、10周开发里程碑

### 第1~2周：基础架构搭建

**目标：** 开发环境就绪，核心基础服务运行

**任务清单：**
- [ ] 搭建Docker Compose本地开发环境（MySQL/Redis/MinIO启动）
- [ ] 执行 `infrastructure/mysql/init.sql` 初始化数据库
- [ ] FastAPI项目骨架（路由注册、JWT中间件、数据库连接池）
- [ ] 用户认证接口（手机号登录、JWT颁发、Token刷新）
- [ ] SQLAlchemy ORM模型（users/communities/assessment_sessions等核心表）
- [ ] React Web管理端项目初始化（Vite + Ant Design + 路由配置）
- [ ] UniApp微信小程序项目初始化（Pinia + 老年主题配置 + manifest.json配置AppID）
- [ ] MinIO桶创建与上传测试

**交付物：** 能登录的Web管理端 + 能运行的微信小程序

---

### 第3~4周：核心评估流程

**目标：** 老年用户能完整跑通一次评估

**任务清单：**
- [ ] 题库数据录入（每认知域至少5题，共30题）
- [ ] 评估会话创建/开始API
- [ ] 题目分发API（先实现顺序分发，自适应后续迭代）
- [ ] 作答提交API（支持单选、语音作答、手写）
- [ ] 手写时钟绘图采集界面（小程序Canvas 2D，坐标序列）
- [ ] 语音任务采集界面（wx.getRecorderManager，录音+上传）
- [ ] 行为数据自动采集（反应时间、点击坐标）
- [ ] 评估完成提交API（返回202 + taskId）
- [ ] Celery任务队列基础配置

**交付物：** 能完成一次评估（数据入库），AI分析暂时返回mock结果

---

### 第5~6周：AI模型集成

**目标：** 真实AI分析结果可输出

**任务清单：**
- [ ] FunASR语音识别接入（中文转写）
- [ ] LibROSA声学特征提取（MFCC、基频、语速）
- [ ] jieba + BERT文本特征提取（词汇丰富度、语义）
- [ ] 时钟绘图评分算法（几何规则评分，CDT 0~10分）
- [ ] LightGBM第一阶段分类器（使用量表得分+行为特征训练）
- [ ] 跨模态注意力融合模型（PyTorch实现 + 公开数据集微调）
- [ ] SHAP值计算与输出
- [ ] 六维认知域得分生成逻辑
- [ ] AI分析结果写入assessment_results表
- [ ] FastAPI推理服务（TorchServe或直接FastAPI endpoints）

**交付物：** 完成评估后能获得真实AI分析报告（分类+SHAP+六维得分）

---

### 第7~8周：干预推荐与可视化

**目标：** 完整闭环（评估→报告→干预推荐）可演示

- [ ] 内容过滤推荐API（基于薄弱认知域）

- [ ] 评估结果报告页（雷达图 + 趋势图 + 通俗解读）
- [ ] 社区医生看板（ECharts：风险分布饼图、月度趋势、预警列表）
- [ ] 家属报告查看页面
- [ ] 老年端结果展示页（简化版，大字体）
- [ ] 高危预警通知推送（站内通知）

**交付物：** 完整演示流程可走通（评估→AI分析→报告→干预推荐→医生看板）

## 三、技术风险与应对策略

| 风险 | 概率 | 影响 | 应对策略 |
|------|------|------|----------|
| **真实老人数据难以获取** | 高 | 高 | 使用公开数据集（DementiaBank + ADNI）+ 合成数据增强；竞赛演示用模拟数据 |
| **多模态Transformer计算量过大** | 中 | 中 | 竞赛版本先用LightGBM（量表+行为特征），ONNX量化部署；Transformer作为"完整版"展示 |
| **国产ASR对老年人方言识别波动** | 高 | 中 | 增加"文字备选输入"备用方案；提示用普通话；质量分不足时提示重录 |
| **UniApp/小程序兼容性风险** | 中 | 中 | 充分测试微信开发者工具与真机差异；Canvas 2D手写画布优先真机验证；订阅消息需提前申请模板ID |
| **时钟绘图AI评分准确率不稳定** | 中 | 低 | 提供"AI评分+人工评分"双通道；竞赛演示时使用规则评分兜底 |
| **演示环境网络不稳定** | 低 | 高 | 演示版本支持离线模式（本地跑Docker Compose）；演示前1天完整演练一遍 |

## 六、演示场景脚本（建议）

**时长：** 约6分钟

```
[0:00 - 0:30] 背景介绍
  "中国3亿老年人，4500万MCI待筛查。传统量表覆盖率低，本系统解决什么问题..."

[0:30 - 2:30] 老年用户完成评估（演示重点）
  - 打开平板App，人脸识别登录（10秒）

  - 社区风险分布图（156人中13高危）

[5:30 - 6:00] 技术创新总结
  "6大创新点快速回顾：跨模态注意力/SHAP可解释/纵向预测/被动监测/游戏化评估/三方闭环"
```
