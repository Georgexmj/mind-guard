# MindGuard 文档导航与现状校准

本文是项目文档入口，用于说明每类文档的用途、当前代码实现边界和推荐阅读顺序。

## 当前实现基线

截至 2026-04-29，项目真实工程结构如下：

| 模块 | 目录 | 说明 |
| --- | --- | --- |
| 后端 | `backend/` | FastAPI、SQLAlchemy、Celery、AI/规则推理、报告生成 |
| Web 管理端 | `web-admin/` | React + TypeScript + Ant Design 管理后台 |
| 微信小程序 | `miniprogram/` | UniApp + Vue 3 老人端 |
| 数据 | `data/` | 合成数据、公开数据拉取脚本、训练清单 |
| 部署 | `docker-compose.yml`, `nginx/`, `infrastructure/` | 容器编排、Nginx、数据库初始化 |
| 文档 | `docs/` | 需求、架构、接口、部署、开发、商业计划 |

需要特别注意：

- 当前没有独立 `frontend/` 目录，前端分别在 `web-admin/` 与 `miniprogram/`。
- 当前没有独立 `ai-engine/` 服务目录，深度多模态模型集成在后端服务内。
- 当前后端接口以前缀 `/api/v1` 暴露，主要路由为 `auth`、`users`、`assessments`、`questions`、`communities`、`dashboard`、`interventions`、`notifications`、`rag`。
- 当前没有单独的 `/api/v1/modality`、`/api/v1/reports` 路由，相关能力合并在评估、干预与通知接口中。
- 所有接口以 FastAPI 原生 JSON 响应为准，不再描述为统一 `{code,message,data}` 包装。

## 修订原则

- 代码事实优先于规划描述。
- 竞赛商业材料可保留愿景表述，但技术、接口和部署文档必须标注“当前已实现”和“后续规划”的边界。
- 涉及部署地址时，优先参考 `.env.example` 与根目录 `docker-compose.yml`。
- 涉及数据库表时，优先参考 `backend/app/models/*.py`。
