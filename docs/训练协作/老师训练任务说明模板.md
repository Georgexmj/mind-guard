# 大模型训练协作任务说明（模板）

## 1. 项目背景与目标

### 1.1 项目背景
- 项目名称：基于多模态交互的社区老年认知障碍早期筛查与干预系统
- 当前线上策略：`AI_MODEL_STRATEGY=hybrid`（规则模型 + 深度模型融合）
- 当前深度模型权重路径：`backend/models/deep_multimodal_fusion.pt`
- 目标：由外部老师团队基于更高质量真实数据训练新版深度模型 checkpoint，并平滑接入现有系统。

### 1.2 本次训练目标
- 训练一个可替换当前 checkpoint 的多模态风险评估模型。
- 输出与现网一致的核心预测语义：
  - 三分类概率：`nc / mci / ad`
  - 六域认知评分：`memory / orientation / language / attention / visuospatial / executive`
  - 模态贡献度：`questionnaire / voice / drawing / behavior`
- 确保可在当前后端服务直接加载，或提供最小化适配改造说明。

## 2. 当前系统约束（必须遵守）

### 2.1 模型加载与运行机制
- 加载服务：`backend/app/services/deep_model_service.py`
- 推理输入是四路结构化特征向量，不是端到端原始音视频。
- 默认配置：
  - `AI_MODEL_STRATEGY=hybrid`
  - `DEEP_MODEL_CHECKPOINT=models/deep_multimodal_fusion.pt`
  - `DEEP_MODEL_DEVICE=cpu`
  - `DEEP_MODEL_ALLOW_RANDOM_INIT=false`
  - `DEEP_MODEL_BLEND_ALPHA=0.65`

### 2.2 兼容性要求
- 优先要求：新 checkpoint 可被当前代码直接加载，不修改线上推理接口。
- 如需变更网络结构，请同时提供：
  - 兼容加载代码补丁（最小改动）
  - 回滚方案（`rule` 或旧 checkpoint 可立即恢复）

## 3. 训练数据格式要求（CSV）

> 训练脚本：`backend/scripts/train_deep_multimodal.py`

### 3.1 行级定义
- 一行代表一个评估样本。
- 最少样本数建议：`>= 1000`（脚本硬约束是 `>= 32`，但不建议低于 1000）。

### 3.2 标签列
- `target_class`：`0=NC`, `1=MCI`, `2=AD`
- 可选六域标签（建议提供）：
  - `target_domain_memory`
  - `target_domain_orientation`
  - `target_domain_language`
  - `target_domain_attention`
  - `target_domain_visuospatial`
  - `target_domain_executive`

### 3.3 特征列（必须）
- `questionnaire_available`
- `questionnaire_quality`
- `questionnaire_choice_accuracy`
- `questionnaire_avg_score`
- `questionnaire_scale_mean`
- `questionnaire_coverage`
- `questionnaire_sample_count`

- `voice_available`
- `voice_quality`
- `voice_word_richness`
- `voice_avg_words`
- `voice_avg_duration_sec`
- `voice_pause_density`
- `voice_audio_file_ratio`
- `voice_sample_count`

- `drawing_available`
- `drawing_quality`
- `drawing_structure_score`
- `drawing_avg_strokes`
- `drawing_avg_points`
- `drawing_image_ratio`
- `drawing_sample_count`

- `behavior_available`
- `behavior_quality`
- `behavior_avg_reaction_ms`
- `behavior_std_reaction_ms`
- `behavior_slow_ratio`
- `behavior_fast_ratio`
- `behavior_stability_score`
- `behavior_sample_count`

### 3.4 数值范围建议
- 比例类字段：`[0,1]`
- 六域评分：`[0,10]`
- 计数类非负；异常值需截断并记录规则。

## 4. 训练任务要求（给老师团队）

### 4.1 数据与实验设计
- 使用真实业务相关数据（优先 DementiaBank / ADReSS / DAIC 等授权数据）。
- 明确训练/验证/测试划分，禁止同受试者泄漏到不同集合。
- 提供类别分布、来源分布、采样策略说明。

### 4.2 训练过程要求
- 固定随机种子（建议提供 3 次复现实验结果）。
- 记录超参：`lr`, `batch_size`, `epochs`, `optimizer`, `weight_decay`。
- 保存最佳 checkpoint（按验证集主指标）。

### 4.3 评估指标（验收）
- 分类指标（必须）：
  - Macro-F1
  - Weighted-F1
  - Recall(AD), Recall(MCI)
  - 多分类 AUC（如可计算）
- 回归指标（六域评分，建议）：
  - MAE / RMSE（逐域 + 平均）
- 工程指标（必须）：
  - CPU 单条推理时延（P50/P95）
  - 模型文件大小
  - 加载成功率

### 4.4 验收门槛（模板，可按会议确定）
- `Macro-F1 >= 0.72`
- `Recall(MCI) >= 0.70`
- `Recall(AD) >= 0.80`
- 六域平均 `MAE <= 1.20`
- 单条推理 `P95 <= 500ms`（CPU）

> 若当前线上基线已测得，应改为“新模型不低于基线，且至少 2 项核心指标提升”。

## 7. 对接与上线步骤

1. 将交付 checkpoint 放置到：`backend/models/deep_multimodal_fusion.pt`
2. 确认 `.env` 中：
   - `AI_MODEL_STRATEGY=hybrid`（或 `deep`）
   - `DEEP_MODEL_CHECKPOINT=models/deep_multimodal_fusion.pt`
3. 重启 `backend` 与 `celery_worker`
4. 进行冒烟测试：
   - 模型加载状态正常
   - 评估任务从提交到结果链路正常
   - 结果字段完整（概率、六域、模态贡献）

## 8. 风险与说明

- 当前项目内存在用于工程联调的自动合成训练集（非临床标注），不能替代正式医学训练数据。
- 任何含个人敏感信息数据须遵守伦理审批和数据使用协议。
- 如老师团队采用端到端原始音视频网络，需要先约定线上特征接口改造范围。
