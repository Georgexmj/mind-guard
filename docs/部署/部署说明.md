# MindGuard 部署说明

**当前口径：** 以根目录 `docker-compose.yml`、`.env.example`、`nginx/` 配置为准  
**修订日期：** 2026-04-29

## 一、部署方式

| 方式 | 适用场景 |
| --- | --- |
| Docker Compose 一键部署 | 演示、验收、生产雏形 |
| 本地开发部署 | 后端、Web、小程序联调 |
| 生产服务器部署 | 域名、HTTPS、微信小程序正式联调 |

## 二、Docker Compose 一键部署

### 1. 准备环境变量

```bash
cp .env.example .env
```

Windows PowerShell 可手动复制 `.env.example` 为 `.env`。

生产环境必须修改：

```env
SECRET_KEY=请替换为强随机字符串
MYSQL_ROOT_PASSWORD=请替换
MYSQL_PASSWORD=请替换
MINIO_ROOT_PASSWORD=请替换
WECHAT_MP_APPID=
WECHAT_MP_SECRET=
```

### 2. 启动

```bash
docker compose up -d --build
docker compose ps
docker compose logs -f backend
```

### 3. 访问

以 `.env.example` 默认值为准：

| 服务 | 地址 |
| --- | --- |
| Web 管理端 | http://localhost:30000 |
| 后端 Swagger | http://localhost:8000/docs |
| 后端健康检查 | http://localhost:8000/health |
| MinIO Console | http://localhost:9001 |

如果修改了 `.env` 端口，请以修改后的端口为准。

### 4. 停止与重置

```bash
docker compose down
docker compose down -v
```

`down -v` 会删除数据库、Redis、MinIO 等数据卷，只在需要重置演示数据时使用。

## 三、本地开发部署

### 1. 启动基础设施

```bash
docker compose up -d mysql redis minio influxdb mongodb
```

### 2. 后端

```bash
cd backend
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python -m app.initial_data
uvicorn app.main:app --reload --port 8000
```

### 3. Celery

```bash
cd backend
.venv\Scripts\activate
celery -A app.tasks.celery_app worker --loglevel=info --concurrency=2 -Q ai_analysis,celery
```

定时提醒：

```bash
celery -A app.tasks.celery_app beat --loglevel=info
```

### 4. Web 管理端

```bash
cd web-admin
npm install
npm run dev
```

### 5. 微信小程序

```bash
cd miniprogram
npm install
npm run dev:mp-weixin
```

用微信开发者工具导入 `miniprogram/dist/dev/mp-weixin`。

## 四、服务清单

根目录 `docker-compose.yml` 包含：

| 服务 | 容器端口 | 说明 |
| --- | --- | --- |
| `mysql` | 3306 | 主业务数据库 |
| `redis` | 6379 | Celery broker/result backend |
| `minio` | 9000/9001 | 对象存储与控制台 |
| `influxdb` | 8086 | 行为时序数据预留 |
| `mongodb` | 27017 | 多模态特征 JSON 预留 |
| `backend` | 8000 | FastAPI |
| `celery_worker` | - | 异步分析 |
| `celery_beat` | - | 定时提醒 |
| `web_admin` | 80 | Web 静态服务 |
| `nginx` | 80/443 | 统一入口 |

## 五、Nginx 配置

当前 `nginx/` 下包含：

| 文件 | 用途 |
| --- | --- |
| `nginx.conf` | 当前 compose 挂载的默认配置 |
| `nginx.dev.conf` | 开发环境参考配置 |
| `nginx.prod.conf` | 生产 HTTPS 参考配置 |

根目录 compose 当前挂载：

```yaml
./nginx/nginx.conf:/etc/nginx/conf.d/default.conf:ro
```

如果要切换配置，需要修改 compose 挂载项或替换 `nginx/nginx.conf` 内容后重建/重启 nginx。

## 六、生产部署建议

1. 使用正式域名，例如 `admin.yishouxinan.site` 与 `api.yishouxinan.site`。
2. 准备 HTTPS 证书并放入 compose 挂载的证书目录。
3. 将小程序 request 合法域名配置为正式 API 域名。
4. 修改 `.env` 中所有默认密码和 `SECRET_KEY`。
5. 将 `DEBUG=false`。
6. 备份 MySQL 与 MinIO 数据卷。
7. 如需要公网开放，只暴露 Nginx 80/443，数据库、Redis、MinIO API 仅内网访问。

## 七、常见排障

### 端口冲突

修改 `.env` 中端口后重启：

```bash
docker compose up -d --force-recreate
```

### 后端连不上 MySQL

```bash
docker compose ps mysql
docker compose logs mysql
docker compose logs backend
```

确认 MySQL 健康检查通过后，再观察 backend 是否完成 `initial_data`。

### AI 分析一直未完成

```bash
docker compose ps celery_worker redis
docker compose logs celery_worker
```

确认 Redis 可用，且 worker 使用 `-Q ai_analysis,celery` 队列。

### Web 页面能打开但接口 404/502

检查 Nginx 与 backend：

```bash
docker compose ps nginx backend web_admin
docker compose logs nginx
docker compose logs backend
```

### 小程序请求失败

- 开发者工具：勾选“不校验合法域名”。
- 生产环境：微信公众平台添加 HTTPS request 合法域名。
- 小程序 API 地址以 `miniprogram/src/config/api.js` 为准。

## 八、演示流程

1. 登录 Web 管理端：`13800000001/admin123` 或 `13800000002/doctor123`。
2. 在看板查看统计、老人列表和评估数据。
3. 老人账号 `13800000003/elder123` 在小程序完成评估。
4. 等待 Celery 分析完成后查看结果。
5. 医生端生成干预计划，老人端打卡，医生端查看依从性预警。
